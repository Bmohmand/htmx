# AGENTS.md

htmx 2.x: a dependency-free browser library that adds AJAX, swaps, history, SSE/WebSocket hooks to plain HTML via `hx-*` attributes. The whole library is one file. Extensions live in a separate repo (bigskysoftware/htmx-extensions); don't add them here.

## Layout
- `src/htmx.js`: the entire library, one IIFE (`var htmx = (function() { ... })()`). Defaults in `htmx.config` (~line 77); public API is wired up as `htmx.process = processNode` etc. (~line 300); `internalAPI` is what extensions receive. Request flow: `processNode` → `addTriggerHandler` → `issueAjaxRequest` → `handleAjaxResponse` → `swap`.
- `test/attributes/hx-*.js`: one mocha suite per attribute; `test/core/*.js`: API, ajax, events, security, regressions. Only these two dirs are run by web-test-runner (`web-test-runner.config.mjs`).
- `test/index.html`: browser-mode runner that lists every test file by hand. A new test file must be added here too.
- `test/manual/`: hand-run HTML pages, not part of `npm test`.
- `www/`: htmx.org (Zola). `www/content/attributes/<attr>.md` per attribute; config options are documented in **two** tables: `www/content/docs.md` and `www/content/reference.md`.

## Commands (repo root)
```
npm ci                                 # install; `npm install` rewrites package-lock.json (see below)
npm test                               # eslint + tsc --checkJs on src/htmx.js + headless Chromium
npm test test/attributes/hx-swap.js    # one file (lint and types-check still run first)
npm run format                         # eslint --fix; run before committing
npm run types-check                    # just the JSDoc type check
npm run test:all                       # chromium + firefox + webkit, what CI runs via test:ci
cd www && zola serve                   # docs site on :1111
```
To run a single test, temporarily change `it(` to `it.only(` and pass the file; remove it before committing.

## Conventions
- `src/htmx.js`: eslint-config-standard (no semicolons, single quotes, 2 spaces) but **no space before function parens**: `function(evt) {`. `.substr` is banned; use `.slice`/`.substring`. Prefer `for...of` over `for...in` on objects.
- Every function in `src/htmx.js` has JSDoc `@param`/`@returns`; `tsc --checkJs` runs inside `npm test`, so new or changed signatures need correct JSDoc types or the suite fails before any test runs.
- Tests use `function()` callbacks (never arrows; they rely on `this.server`) and `var`. Standard shape:
  ```js
  beforeEach(function() { this.server = makeServer(); clearWorkArea() })
  afterEach(function() { this.server.restore(); clearWorkArea() })
  it('swaps content', function() {
    this.server.respondWith('GET', '/test', 'Clicked!')
    var btn = make('<button hx-get="/test">Click Me!</button>')
    btn.click()
    this.server.respond()
    btn.innerHTML.should.equal('Clicked!')
  })
  ```
  Helpers (`make`, `byId`, `makeServer`, `clearWorkArea`) are in `test/util/util.js`; assertions are chai `should`; stubs are sinon and get restored in `afterEach`.
- Behavior changes ship with a test in `test/` and a doc update in `www/content/`.

## Guardrails
- Upstream PRs for code target `dev`; PRs touching only `www/` target `master`. This is about where a PR is opened, not which branch to work on locally; don't warn about or switch branches unless asked to prepare a PR.
- Never hand-edit `dist/` or `src/htmx.esm.d.ts` (a copy of generated types) and don't include them in changes; maintainers rebuild them at release with `npm run dist`.
- `www/static/src/`, `www/static/test/`, `www/static/node_modules/` and `www/themes/htmx-theme/static/js/htmx.js` are **stale copies** made by `scripts/www.sh`. Grep hits there are not the source; edit `src/` and `test/` instead.
- `coverage/` is regenerated by every test run; ignore it.
- `npm install` rewrites `package-lock.json` (the lockfile lags the package version); don't commit that churn, and don't run the `npm audit fix` that `npm ci` suggests. The `EBADENGINE` warning for `errorstacks` (wants Node 24) is harmless; tests pass on Node 22.
- `npm run dist`, `www`, `sha` call bash scripts and fail on Windows under npm's default shell (`'.' is not recognized`). Use `bash scripts/dist.sh` from Git Bash if a build is really needed.
- Pure refactors without a functional change are closed by maintainers; keep diffs minimal.
